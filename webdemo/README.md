# Web demo architecture

Vanilla HTML/CSS/JS with ES modules — **no build step, no framework**. Any
static file server can host it; the only external dependency is the
`onnxruntime-web` script from a CDN.

```
webdemo/
├── index.html        markup only; loads onnxruntime-web (global `ort`) and js/main.js
├── css/
│   └── style.css     all styles
├── js/
│   ├── main.js       entry point: page state, control wiring, metrics table
│   ├── config.js     the contract with the exported graph (sizes, levels, model paths)
│   ├── forecaster.js onnxruntime-web: session cache, NaN-pad input, run, unpack
│   ├── data.js       bundled datasets + CSV upload parsing
│   ├── metrics.js    ONNX-vs-library diff stats, MAE
│   └── plot.js       canvas chart (history, actuals, quantile fan, library median)
└── data/             generated by ../scripts/make_demo_data.py:
    ├── index.json    dataset list the page discovers
    ├── *.json        series + PyTorch reference forecasts
    └── *.csv         raw datasets (handy for testing the upload feature)
```

## Data flow

```
pick dataset / upload CSV ──▶ data.js ──▶ normalized {context, actuals, refs}
                                              │
                                              ▼
                            forecaster.js: NaN-pad → [1,512] tensor → session.run
                                              │
                                              ▼
                              quantiles [64 steps][5 levels]
                                    │                │
                                    ▼                ▼
                             plot.js (chart)   metrics.js + main.js (table)
```

## Things worth knowing before editing

- **`config.js` values are baked into the `.onnx` files.** Changing
  `CONTEXT_LEN`/`HORIZON` here without re-running `scripts/export_t0_onnx.py`
  produces silently wrong results.
- **NaN is a feature.** The model treats NaN as "missing"; the demo
  left-pads short series with NaN and renders gaps for missing values.
- **Why the global `ort` instead of an ES import**: the UMD bundle
  resolves its `.wasm` binaries relative to the CDN URL automatically.
  Zero config, zero build. If you move to a bundler, switch to the
  `onnxruntime-web` npm package and configure `ort.env.wasm.wasmPaths`.
- **Serving**: serve the *repo root*, not this folder — the page reaches
  up for `../onnx/*.onnx`. `file://` won't work (fetch + WASM need HTTP).
- The engine itself is regression-tested in [`../tests/`](../tests/README.md)
  (same WASM kernels, run under Node).
