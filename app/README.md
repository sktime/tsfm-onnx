# app/ - the browser forecasting tool

Vanilla HTML/CSS/JS with ES modules. **No framework, no build step**: the
page is one static folder any file server can host, and the only external
dependency is the `onnxruntime-web` script from a CDN. (A framework was
considered and rejected on purpose: one page, six small modules, no routing
and no shared components means a bundler would add a toolchain without
buying anything. If this ever grows into a multi-page site, Astro would be
the natural upgrade.)

```
app/
├-- index.html        markup only; loads onnxruntime-web (global `ort`) and js/main.js
├-- css/
│   └-- style.css     the whole theme: tokens, pills, layout, chart chrome
├-- js/
│   ├-- main.js       entry point: state, control wiring, metric tiles, table, CSV export
│   ├-- config.js     the contract with the exported graphs + MODEL_BASE for hosting
│   ├-- forecaster.js sessions with download progress; univariate + joint inference
│   ├-- data.js       bundled datasets, CSV parsing (multi-column, labels), compare modes
│   ├-- metrics.js    forecast-vs-library and forecast-vs-actuals math
│   └-- plot.js       canvas chart: bands, crosshair tooltip, keyboard access
└-- data/             generated by ../scripts/make_demo_data.py:
    ├-- index.json    dataset list the page discovers
    ├-- *.json        series + PyTorch reference forecasts
    └-- *.csv         raw datasets (handy for testing the upload feature)
```

## Features

- **Three models** behind one picker (config.js registry): Chronos-2,
  TinyCast and TinyTimeMixer r2, each with its own context length, horizon
  and inference driver. The app displays POINT forecasts only (the median
  where a model emits quantiles).
- Sample datasets with **library reference forecasts** overlaid (computed
  with the chronos-2 PyTorch pipeline, so shown only for that model), so
  the browser-vs-PyTorch difference is measured on screen.
- **CSV upload** (click or drag): multi-column files get a series picker;
  the first non-numeric column becomes x-axis labels; empty/NA cells are
  treated as missing (chronos-2 handles NaN natively; for tinycast/TTM the
  forecaster imputes by linear interpolation, matching the official
  tinycast predictor).
- **Joint multivariate mode** (chronos-2 only): forecast all columns of an
  upload together through the grouped graph (`group_ids` input).
- **Check against**: backtest (hold out the model's horizon) or upload a
  separate test CSV with the actual future; metric tiles report MAE.
- **Table view + CSV download** of the forecast.
- int8 / fp32 precision switch and a real download progress bar.

## Data flow

```
dataset pick / CSV upload --> data.js --> {context, actuals, refs, labels}
                                              │
                                              ▼
      forecaster.js: per-model packing -> session.run [-> AR rollout (tinycast)]
                                              │
                                              ▼
                             point forecast [horizon steps]
                            │              │               │
                            ▼              ▼               ▼
                     plot.js (chart)  metric tiles   table + CSV export
```

## Things worth knowing before editing

- **`config.js` values are baked into the `.onnx` files.** Changing
  `CONTEXT_LEN`/`HORIZON` there without re-exporting produces silently
  wrong results. `MODEL_BASE` is the one value meant to be edited: point it
  at wherever the model files are hosted (see the repo README's Hosting
  section).
- **NaN is a feature.** The model treats NaN as "missing"; short series are
  left-padded with NaN, and the chart renders gaps for missing values.
- **CSV headers are untrusted input.** Column names go into the DOM via
  `textContent` only - keep it that way.
- **Why the global `ort` instead of an ES import**: the UMD bundle resolves
  its `.wasm` binaries from the CDN automatically. Zero config, zero build.
- **Serving locally**: serve the *repo root*, not this folder - the page
  reaches up for `../onnx/*.onnx`.
- The chart follows the repo's dataviz conventions (validated palette,
  crosshair tooltip listing every series, keyboard navigation, table view
  as the accessible fallback). The engine itself is regression-tested in
  [`../tests/`](../tests/README.md) under the same WASM kernels.
